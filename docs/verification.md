`backend/tests/preview.py`는 합성 시계열 120개와 모의 생성 결과를 사용하는 로컬 테스트 서버입니다. Render 시작 명령은 `app.main:app`이며 테스트 서버를 사용하지 않습니다.

스크린샷은 이 합성 테스트 환경의 화면입니다. 실제 개인 데이터/GPT 응답이나 배포 증빙으로 제출하면 안 됩니다.

## 구현 범위와 제한

- 단일 개인 사용자부터 시작하며 ALLOWED_USER_UIDS로 명시적으로 허용한다.
- 서버가 컬렉션을 소유자별 조회 후 메모리에서 기간·검색을 처리한다. 10,000문서를 넘으면 잘못된 부분 결과 대신 오류를 반환한다. 대규모 사용 전 서버 쿼리와 페이지네이션이 필요하다.

- 수식 편집은 LaTeX 원문을 보존한다. 초기 화면은 원문 표기이며 수식 조판 렌더링은 후속 개선이다.
- 일반 선호는 사용자가 직접 확인 후 저장한다. 피드백은 자동으로 영구 선호로 승격하지 않는다.

### 독립 검토와 수정

새 문맥의 독립 코드 검토에서 발견한 7개 중요 사항을 검증하고 수정했다. 재검토를 반복하지 않고 재현 테스트가 실패한 것을 확인한 뒤 수정해 통과시켰다.

1. 실제 FirestoreStore의 계약에는 루트 `set`이 없었다. 수집 세대 쓰기를 기존 `atomic`/트랜잭션 `set`으로 바꿨다. 운영 어댑터와 같은 계약의 테스트 및 실제 승인된 저장·재조회를 통과했다.
2. `allSettled`의 이미 완료된 오래된 결과가 로그아웃 이후 다시 표시됐다. refresh와 세션의 전체 비동기 경계에 계정 세대 검사를 추가했다.
3. 결과 불명의 503에서 상담 UUID를 지웠다. 503에서는 원래 요청을 보존하고 상태 조회로 복구한다. 동기화도 같은 규칙을 적용했다.
4. 이전 대화를 복원하며 미완료 follow-up UUID를 지웠다. 메시지 복원과 미완료 요청을 별도로 유지한다.
5. 워커가 중단되면 pending이 영구히 남았다. 상태 조회가 완료 여부를 먼저 읽은 뒤 만료된 180/600초 예약을 안전하게 실패 처리한다. 다른 활성 요청은 해제하지 않는다. 삭제된 대화 요청의 빈 문서 ID 조회도 회귀 테스트로 방지했다.
6. 7일차 값과 현재 누적 갱신 시각이 섞였다. 선택한 관측의 수치·소스 시각·수집 시각을 함께 전달하고 현재 시각은 별도 필드로 보관한다.
7. 게시물 하나를 저장하거나 더 불러오면 다른 게시물의 입력이 사라졌다. 게시물 ID별 편집 초안을 유지하고 저장한 항목만 지운다.
