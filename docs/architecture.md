# Next Post 구조

## 사용자 흐름

Instagram 대화에서 게시물 검색·초안 비교·재활용·게시 결과·시리즈를 질문한다. 초안 이미지는 첨부하고 참고할 기존 글은 지난 게시에서 선택할 수 있다. 질문과 관련된 아직 안 읽은 글은 최대 하나를 읽어 저장한 뒤 대화에 사용한다. 작업 결과와 근거를 확인하고 GPT에서 이어갈 자료를 복사한다. 통계·시간 비교·실험은 접힌 선택 기능이며 필수 시계열 CRUD·요약과 대화 기록은 유지한다.

## 구성 요소

```text
Vercel 정적 HTML/CSS/JS
  → Firebase Google 로그인 → Firebase ID token
  → Render FastAPI
      ├ auth.py: 허용 UID와 인증
      ├ buffer_client.py: 고정 읽기 쿼리와 외부 응답 검증
      ├ buffer_service.py: 소유 UID·쿼터·동기화 세대·성공 포인터
      ├ growth_analytics.py: 전환율·형식별 집계·시간 후보·결측 이유
      ├ growth_service.py: 근거·7일차 관측·실험 연결
      ├ post_media.py: 서버 소유 첨부물의 제한된 다운로드·이미지 정규화
      ├ post_reading_service.py: 이미지 판독 기억·출처 일치·예약·UUID 복원
      ├ image_review_generation.py: 설정된 제공업체의 이미지 판독·검토
      ├ analytics.py: 계정 일별 시계열 요약
      ├ chat_service.py: 예약·컨텍스트 준비·생성·자동 저장·UUID 복구
      └ generation.py / anthropic_generation.py: 선택한 제공업체의 구조화 응답과 근거 ID 검증
  → Firestore (서버 Admin SDK)
```

Pydantic은 요청의 필드·길이·날짜·시간대·수치·모드와 알 수 없는 필드를 검증한다. Buffer의 신뢰하지 않는 외부 응답도 고정 계약으로 확인한다. 라우터는 HTTP·인증을 담당하고 통계 함수는 네트워크와 분리한다.

## 저장과 일관성

`data`는 계정 일별 관측, `buffer_syncs/{id}/posts`는 특정 수집 시점의 게시물별 누적 성과다. 두 자료는 혼합하지 않는다. `buffer_connections`의 성공 포인터는 전체 페이지 저장 후에만 바뀐다. 동기화 실패·부분 저장 중에는 이전 세대를 읽는다. 개인 키는 환경 변수에만 있다.

`post_annotations`는 태그·메모·수동 값을 원본과 분리한다. `growth_recommendations`와 `growth_experiments`는 당시 기준·관측 방식·선택한 후보·근거와 실제 게시물 연결을 남긴다. 플랫폼 값에 수동 값을 덮어쓰지 않는다.

`post_readings`는 소유자·게시물별 판독 본문·요약·주제·장별 판독 여부와 출처 서명을 저장한다. 서명에는 캡션과 순서가 보존된 첨부물 메타데이터가 포함된다. 갱신 때 만료 서명만 바뀐 URL은 재사용하고 실질 출처가 바뀌면 재판독한다. 같은 안정 URL의 원격 파일이 덮어써진 것은 메타데이터만으로 감지할 수 없다. `post_reading_requests`의 UUID 예약은 동일 게시물의 중복 호출을 막고, 실제 판독은 대화와 같은 사용자 일일 쿼터를 사용한다. 원본 이미지 바이트는 서버 DB에 저장하지 않는다.

## 컨텍스트 주입

1. `/api/data/summary`와 채팅은 동일한 `summarize()` 계산을 사용한다.
2. 성장 상담은 현재 성공한 수집 세대에서 형식별 통계·시간 후보를 계산한다.
3. 계산된 숫자는 시스템의 데이터 요약에 넣는다. 캡션·주제·메모·과거 메시지는 별도의 신뢰하지 않는 참고 입력이다.
4. 선택한 글·질문 관련 캡션 및 판독 본문·전환율 상위·최근 글을 섞어 상세 근거 최대 5개를 선택한다. 최근 최대 60개의 캡션 일부와 저장된 판독 요약도 제공한다. 새 초안 이미지는 네이티브 이미지 입력으로 전달한다. 모델은 질문에 맞는 답변과 필요한 `work_text`를 작성하며 시간 후보와 수치는 서버 결과를 붙인다.
5. 모델의 참조 ID를 제공한 상세 근거 및 캡션 이력의 ID로 제한한다. 캡션만 참고한 글은 화면에서도 성과 수치가 없는 자료로 구분한다. 사용자·답변·추천 카드·근거를 하나의 완료 트랜잭션에서 저장한다.
6. 같은 UUID를 다시 요청하면 저장된 결과를 돌려준다. 저장 확인이 어려우면 새 UUID로 재생성하기 전에 상태를 조회한다.

성장 모드는 기존 `LLM_PROVIDER`와 같은 생성기를 사용한다. Anthropic을 선택했다면 준비된 Anthropic 호환 API를 그대로 사용하고 OpenAI 키를 별도로 요구하지 않는다. 선택한 제공업체의 키가 없을 때만 상담을 차단한다. Buffer API가 Instagram 자료의 기본 수집 경로이며 CSV는 과거 계정 일별 자료를 보완하는 접힌 선택 기능이다.

## 해석 범위

팔로우가 알려지고 도달이 양수인 같은 형식끼리 전환율을 비교한다. 누적 성과는 경과 시간이 서로 다르다. 실제 저장된 소스 갱신 시점이 게시 후 6~8일인 관측만 7일차 부근 비교에 쓴다. 관측을 놓치면 결측이다. 한 번의 관측으로 추천 시각의 인과나 성장 개선을 확정하지 않는다.

## 운영 경계

Buffer 개인 자료는 `BUFFER_OWNER_UID` 하나에 연결한다. Firebase·Buffer·모델 키는 서버 전용이며 프론트에는 공개 Firebase 설정과 API 주소만 빌드한다. CORS는 정확한 프론트 origin을 허용한다. 모든 Firestore 문서는 소유권을 검사한다. 로컬 테스트 API·합성 생성기는 운영 앱이 가져오지 않는다.
