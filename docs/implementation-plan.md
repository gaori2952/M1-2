# 구현 계획 · 2026-10-17

현재 저장소의 architecture.md와 승인한 제작 비서 흐름을 구현한다.

1. 인증·설정·입력 검증: Firebase ID 토큰과 허용 UID, 테스트 전용 의존성 주입.
2. 데이터·콘텐츠 CRUD와 멱등 CSV 가져오기: 사용자 범위, 결측 보존.
3. 통계·검색: 같은 기간 비교, 0과 결측 구분, 선택한 근거 우선.
4. 개인화 생성: 프로필/시리즈 규칙, 구조화 출력, 요청 중복·일일 제한, 원자적 저장.
5. 대화·초안 복원: 순서, 버전 충돌, 편집 피드백, 확인 후 선호 반영.
6. 바닐라 화면: 로그인, 작업실, 라이브러리, 데이터, 기록, 내보내기.
7. 테스트·배포 설정·실제 연결: 모의 검증과 실제 외부 서비스 검증을 분리한다.

## 이번 저장소에 맞춘 결정

- 기존 계획의 content-agent/ 하위 폴더 대신 이 저장소 루트에 backend/와 frontend/를 둔다.
- 깨끗한 전용 작업 폴더의 기능 브랜치에서 작업한다. 별도 작업 폴더 복제는 하지 않는다.
- 소유자 필드 이름은 현재 공개 설계의 owner_uid로 통일한다.
- 개인 대화 원문과 실제 CSV는 .private/에만 준비하고 공개 Git에 포함하지 않는다.
- 원격 인증·배포 자격 증명이 없으면 운영 인증 우회 없이 테스트에서만 저장소·인증·모델을 대체한다.
- 모든 하위 기능의 HTTP 계약은 같은 Pydantic 모델을 사용한다. 모델 출력과 저장 버전은 별도 검증한다.

## 검증 기준

권한 없는 접근 차단, 다른 사용자 자료 격리, 결측·기간 비교, CRUD 후 요약 변경,
자료 선택, 모델 출력 오류·비용 제한·중복 요청, 대화 복원·삭제, 초안 버전 충돌,
확인된 선호만 적용, UI 입력 보존·악성 HTML 비실행을 테스트한다.
실제 Firebase/OpenAI와 배포 검증 여부는 docs/verification.md에 기록한다.
